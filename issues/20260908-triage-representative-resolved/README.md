# vuoi triage: 代表カード自身が「解決済み」と判定された場合の扱い

Status: OPEN

## What

Inbox トリアージで、重複クラスタの代表カードが同じランで「解決済み」と判定されたときに
何が起きるかを調べ、仕様（`docs/spec/inbox-triage.md` の行動の決定表）に定めが無い
このケースについて、取りうる方針を整理して申告する。実装は行わない。

- 調査対象のコードは main には未マージで、ブランチ `chevuoi/trello-qNH3k8sL`
  （コミット 18d4000「vuoi トリアージ機能の実装- #34」）にある。
  本ワークツリー（`chevuoi/trello-emD4FY1Q`）には `triage_usecase.py` も
  `docs/spec/inbox-triage.md` も存在しない。
- 再現は `chevuoi/trello-qNH3k8sL` のツリーを `/tmp` に展開して行う。
  リポジトリのソースは変更していない。

## Why

代表カードだけは鮮度判定の対象から外れていないため、同じランで
「代表を archive」と「重複を代表へ merge」が同時に成立しうる。
決定表は 1 枚ごとの行動しか定めておらず、クラスタ全体の不変条件
（集約先はそのランを生き残る）を定めていない。実装時に推測で決めない。

## メモ（要点）

- 主張は成立。失われ方は代表と重複の本文が一致するかで分かれる。本文が違えばカードの
  記述どおり集約コメントがアーカイブ済みの代表に残り、本文まで同一なら digest 衝突で
  投稿されない。畳んだ先を指すコメントはどちらでも重複側に残る。
- 代表が archive されるかはクラスタの作られ方（完全一致 / LLM 判定）で分岐するため、
  現状は「方針 (3) 現状のまま」と呼べる一貫した状態ですらない。
- 調査としては方針 (1)（クラスタに属する間は代表も鮮度判定しない）を推す。仕様が既に
  使う「解決済み判定は次のランへ持ち越しても損失がない」論法に乗せられる。ただし
  **台帳の手当てが要る**: 前回 `keep` で終わったカードは内容が変わらない限り再判定
  されないため、見送った鮮度判定は次のランで拾い直されない（現状の LLM クラスタでも
  同じ取りこぼしが起きている）。
