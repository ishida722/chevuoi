# dev ワークフローで実装ノードが差分ゼロのまま完走する件（調査）

Status: OPEN

## What

vuoi の dev ワークフローで、`plan_implement` が `ok=True` を返しながらファイルを一切変更せず、
そのままテストゲート・`/code-review` を通過して終端まで進む回がある。
対象事例: 未来リサーチ 後処理MA補正の実装 (trello:k7xziIiV) の 2026-09-01 19:39 の回
（カード本文は同カードが 4 回処理されたとするが、ログ・reflog・カードのコメントはいずれも 3 回）。

問い:
- 実装ノードの前後で差分の有無を決定的に確認し、差分ゼロなら blocked にして人間へ返すべきか
- それとも実装ノードのプロンプト・入力側に問題があるのか

## Why

差分ゼロのまま「正常終了」すると、カードは In review へ移動し人間の確認待ちになるが、
実際には何も進んでいない。今回はその判明後の 3 ノードで $4.09 とテスト 2 回が無駄になった。
再投入すればさらに同じコストがかかる（今回の再投入は人間が起こしたもので、結果的には成功している）。

## メモ

- 19:39 の回の差分ゼロは、実装ノードが書き込みを全拒否されたため（chevuoi 8adde6e の
  `--permission-mode auto` で解消済み）。プロンプト・入力の問題ではなかった。
- 残件は「作業できなかった回（blocked にすべき）」と「変更不要と判断した回（現行の変更なしでよい）」を
  区別する手段が無いこと。判別には実行結果 JSON の `permission_denials` が使えそうだが、
  CLI の説明によればフック deny・deny ルール・MCP 経由の拒否は記録対象外なので、網羅性は未確認。
