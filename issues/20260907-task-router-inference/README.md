# vuoi タスクルーターが弱い — 現状整理と変更方針

Status: OPEN

Trello: https://trello.com/c/BMteMbAP/2014

## What

カード→ワークフローのルーター（`ClaudeWorkflowRouter` / `SelectWorkflowUsecase`）が、カード本文に作業種別を明示しないと正しく決まらない、という問題の現状を整理し、変更方針をまとめる。この調査ではリポジトリのソースコードを変更しない。

## Why

ルーターはカード1枚につき必ず1回走る入口の判断で、誤ると実行1本ぶん（worktree 作成・`claude` 実行・PR 作成まで）を無駄にする。仕様上も「改善 ROI が最も高い」と位置づけられている（`docs/spec/cli.md`）。一方で現状は棄権がほぼ発生せず、誤ルーティングが可視化されないため、まず何が弱いのかを事実で切り分ける必要がある。

## Tasks

- [x] ルーターの実装を読み、入力・プロンプト・出力・棄権条件を把握する
- [x] 3層 triage（決定的マーカー / LLM / 棄権）の各層が実運用でどれだけ効いているかをログで測る
- [x] 仕様（`docs/spec/triage.md`・`docs/spec/workflow-engine.md`）と実装の乖離を洗い出す
- [x] プロンプトの変更履歴を追い、現在の判断ルールが何を直すために入ったかを確認する
- [x] 「明示しないと決まらない」の原因を分解し、変更方針としてまとめる
- [x] 報告書（report.md）にまとめる

## メモ

- 「弱い」の実体は棄権の多さではなく明示への依存。実運用 106 件で推論による棄権は 0 件、選択先は `dev` が 58%、理由の 1 割強（12/106）がカード本文の自己申告を根拠にしていた。
- 原因はモデルではない（`[router]` 未設定のまま Claude Code の既定モデルを使用。仕様が推奨する軽量モデルにすら絞っていない）。プロンプトが「確信度はカードの記述の明確さだけで決めろ」と推論を禁じ、入力がタイトルと本文しかなく、第1層マーカーは `[card.dev]` 形式でしか効かず 0 件だった。
- 方針は「明示を要求せず、推論の材料と判断軸を与える」。ただし棄権パスと「LLM は名前1つだけ」は維持し、効果を測れないまま変えないよう測定基盤を先に置く。
- 詳細は [report.md](report.md) を参照。
