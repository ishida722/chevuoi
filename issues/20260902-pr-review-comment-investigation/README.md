# vuoi コードレビューワークフローで PR にコメントが付かない現象の調査

Status: OPEN

## What

Trello カード「vuoi コードレビューワークフローでPRにコメントをつけてくれない現象調査」
（https://trello.com/c/bKQ0DuU1/）の調査。

- vuoi のコードレビュー経路が GitHub の PR にコメント（インラインの行コメント／通常コメント）を
  残さないのはなぜかを突き止める
- カード本文の問い「PR コメント・コードコメント・レビュー下書きまでしてほしい、可能か？」に答える

## Why

PR レビューを vuoi に任せたいが、現状はレビュー結果が Trello カードのコメントにしか残らず、
GitHub 側に何も付かない。原因が「実装されていない」のか「実装はあるが動いていない」のかで
打ち手が変わるため、先に事実を確定させる。

- [x] 設計文書 docs/design/20260830-pr-review-workflow/design.md と実体の差分を確認する
- [x] `/code-review` の呼び出し方（引数・セッション・権限）を確認する
- [x] 実行ログ・トランスクリプトで実際の挙動を裏取りする
- [x] 実現可能性（PR コメント／コードコメント／レビュー下書き）を整理して report.md にまとめる

## メモ（要点）

- PR にコメントが付かないのはバグでも権限不足でもなく、決定的な投稿経路が未実装で投稿が LLM の裁量任せになっているため。PR レビューのカードは `task` に振られるが、`task` はホスト側に GitHub への出口を持たず、プロンプトにも投稿の指示が無い。実測 3 回のうち、人間が「PRコメントに入れて」と明示した 1 回だけ `gh pr comment` が実行され投稿に成功している（PR #143 の issuecomment-5497811621）。`dev` の `/code-review` は `--comment` 無しで、初回は PR 作成前・未コミット差分に対して走るため PR には書けない。
- 設計 `docs/design/20260830-pr-review-workflow/design.md` は本件を解いているが、第 1 段階の `pr_review` ワークフローすら未作成。`gh` は `repo` スコープで認証済み、`--permission-mode auto` も入っており、投稿の環境条件は揃っている（実投稿の成功で裏取り済み）。なおルーティングで参照されている「他 PR のレビュー」は `task/workflow.toml` の `summary` にあり、`when_to_use` ではない。
- PR コメント・インラインのコードコメント・レビュー下書き（reviews API で `event` 省略 → PENDING）はいずれも実現可能。PR コメントは現状のままでも実績あり、残るはそれを決定的にすること。まず設計の第 1 段階を実装するのが最短。ただし下書き（`event` 省略）は設計の「`event` は常に `COMMENT`」からの変更にあたる。
