# 経路とノード

## 経路の定義

経路は、実行するノードの列と、失敗時の戻り先・試行上限・予算をまとめたものです。4つの経路を定義します。

### implement（実装）

| 項目 | 内容 |
|---|---|
| ノード列 | worktree 準備 → 計画 → 実装 → ゲート → レビュー → PR 作成 |
| ゲート | あり |
| 失敗時の戻り先 | ゲート失敗 → 実装、レビュー指摘 → 実装 |
| 試行上限 | 実装 3回、ゲート 3回 |
| レビュー上限 | 3ラウンド |

### trivial（軽微な修正）

| 項目 | 内容 |
|---|---|
| ノード列 | worktree 準備 → 実装 → ゲート → PR 作成 |
| ゲート | あり |
| 失敗時の戻り先 | ゲート失敗 → 実装 |
| 試行上限 | 実装 2回、ゲート 2回 |
| レビュー上限 | 1ラウンド |

### investigate（調査）

| 項目 | 内容 |
|---|---|
| ノード列 | 調査 → 執筆 → レビュー |
| ゲート | なし |
| 失敗時の戻り先 | レビュー指摘 → 調査 |
| 試行上限 | 調査 2回 |

### design（設計判断）

| 項目 | 内容 |
|---|---|
| ノード列 | ADR 起草 → レビュー → 人間承認 |
| ゲート | なし |
| 失敗時の戻り先 | レビュー指摘 → ADR 起草 |
| 試行上限 | ADR 起草 2回 |

worktree の準備は、必要とする経路にだけ含めます。investigate / design はリポジトリの clone を必要としないため、無駄な clone と後始末が発生しません。

ゲートの有無は経路が決め、ゲートの中身（実行コマンド）はプロジェクトが決めます。実装上は `config.toml` の `[projects.<tag>].test_commands` が中身で、ワークフローは `ctx.project.test_commands` から読みます（{doc}`workflow-engine`）。

```toml
[projects]
short = "/path/to/repo"            # 短縮形（test_commands なし）

[projects.chevuoi]                 # テーブル形式は末尾にまとめる
path = "/path/to/chevuoi"
test_commands = ["uv run pytest -q tests/unit"]
```

ゲート有りの経路でコマンドが未設定なら、通過扱いにせず `blocked` で止めます。「ゲートを通ったように見える PR」を出さないためです。

## ノードへの入力の制限

各ノードには、宣言された入力だけを渡します。「これまでの全部」を渡しません。

| ノード | 入力 |
|---|---|
| 計画 | チケット、対象ファイル候補 |
| 実装 | 計画、未解決の所見、最新のゲート結果 |
| ゲート | なし（LLM 不使用） |
| レビュー | diff、受け入れ基準、凍結済みの所見 |
| 調査 | チケット |
| 執筆 | 調査メモ、チケット |
| ADR 起草 | チケット、未解決の所見 |

特にレビューには、計画と実装の会話を渡しません。ノードごとにプロセスを分けている唯一の理由が新鮮なコンテキストの確保であり、レビューに計画を渡すと「計画通りだから OK」という採点が始まるためです。

## ノードの実行条件

LLM を使うノードは `claude -p` の1回の呼び出しとして実行し、次の制約を課します。

- 使用できるツールをノードごとに最小権限で明示する
- ターン数の上限をノードごとに設定する

| ノード | 許可ツール | ターン上限 |
|---|---|---|
| triage | 読み取り・検索 | 5 |
| 計画 | 読み取り・検索・git 履歴の参照 | 10 |
| 実装 | 読み取り・編集・作成・コマンド実行 | 40 |
| レビュー | 読み取りのみ | 10 |
| 調査 | 読み取り・検索・Web 検索 | 20 |

セッションの継続は既定で使いません（毎回新規セッション）。ゲート失敗からのリトライでセッションを再開すると、失敗した推論ごと復活するためです。同一ファイルの単純な修正のみセッションを再開してよく、方針から誤っていた場合は新規セッションとします。

ノードの成否は LLM の自己申告（「完了しました」）ではなく、終了コードと構造化出力から判定します。

## 停止条件は2層

- **ノード内**: ターン数の上限
- **ラン全体**: ノードごとの試行回数上限と、壁時計での時間予算（既定 45 分）

片方だけでは不十分です。ノード内の上限だけだと、5ターンで終わるノードが30回リトライされて一晩溶けます。
