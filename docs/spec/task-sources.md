# タスクソース連携

## タスクソースとは

タスクソースは、チケットの取得元となるタスク管理ツールです。初期対応は Trello のみで、将来的に Jira / GitHub Issues などへの拡張を想定します。

各タスクソースは次の操作を提供します。

| 操作 | 内容 |
|---|---|
| 取得 | 実行可能なチケットを一覧する |
| クレーム | チケットを占有し、二重実行を防ぐ |
| 結果反映 | 終端状態に応じてチケットを更新する |
| コメント | チケットへコメントを付ける |
| 有効性確認 | チケットが実行中に外部で変更されていないか確認する |
| 起票 | 副次タスクを新規チケットとして作成する |
| 類似検索 | 起票候補と重複する既存チケットを探す |

「どのチケットが実行対象か」の条件は各タスクソースが定義します。Trello なら「Ready リストの chevuoi ラベル付きカード」、Jira なら JQL による指定です。

## チケットが持つ情報

チケットからシステムへ渡る情報は次のとおりです。

- 取得元（ソース名・外部 ID・URL）
- タイトルと本文
- タグの一覧
- 世代深度（人間起票 = 0。自動起票されるたびに +1）
- 親タスクへの参照（自動起票の場合のみ）

## Trello 連携の仕様

### チケットの取り扱い

- 実行対象は Ready リストのカード
- クレームは「In Progress リストへの移動」で表現する
- カードが既に In Progress にある場合、自分の中断ランの再開であればクレーム成功として扱い、そうでなければ失敗として扱う
- カードが Ready 以外のリストにある場合（他者が取った・人間が動かした）、クレームは失敗する

### 終端状態のカードへの反映

| 終端状態 | カード操作 |
|---|---|
| `done` | In Review へ移動し、PR の URL をコメント |
| `needs_human` | Blocked へ移動し、未解決の所見をコメント |
| `failed_gate` | Blocked へ移動し、ゲートのログをコメント |
| `oscillation` | Blocked へ移動し、diff の履歴をコメント |
| `failed_budget` | Blocked へ移動し、超過理由をコメント |
| `abandoned` | 何もしない |

反映方法が定義されていない終端状態が生じた場合は、コメントのみへフォールバックします。

### 冪等性

クレームやカード更新は冪等に動作しなければなりません。cron の二重起動やクラッシュ後の再開でカードが二重に動くことは許容しません。

### MCP を使わない

Trello との通信は REST API を直接使い、MCP コネクタは使いません。MCP は Claude が使うための仕組みであり、パイプライン側が使うとカード操作が非決定的になり、リトライの冪等性が壊れるためです。

## PR レビュー依頼の取り込み

自分にレビューが依頼されている GitHub の PR を、定期的にカードとして起票します。取得は `gh`（認証済みの CLI）で行い、対象は open で `review-requested:@me` の PR です。

- **プロジェクトの特定は決定的に行う。** PR のリポジトリ（`owner/name`）と、設定のプロジェクトのリポジトリを照合します。プロジェクトのリポジトリは設定の `repo` を優先し、無ければそのプロジェクトの `origin` のリモート URL から求めます。`repo` は `owner/name` でも URL（`https://github.com/owner/name` や `git@github.com:owner/name.git`）でも書け、リモート URL と同じ規則で解釈します。大文字小文字は区別しません。
- **マッチすればプロジェクトタグを付けて起票し、マッチしなければタグ無しで起票します。** レビューを人間が行うか、レビューのワークフローに流すかは人間が判断します（起票先は Inbox なので自動では実行されません）。
- **1 回の取得件数には上限があります。** 取得は更新の新しい順で、上限に達した場合はそれより古い依頼がカード化されないため、警告を出します。
- **同じ PR のカードは 1 枚に収束します。** 冪等キーはリポジトリと PR 番号だけから決まるため、PR のタイトルが変わっても同じカードを指します。既存カードはボード全体から探すので、Inbox から動かしたあとに再実行しても二重に起票されません。カードの本文には PR の URL を載せ、レビューのワークフローが対象 PR を特定できるようにします。カードをアーカイブした場合は既存として拾えないため、レビューしないと決めた PR は GitHub 側でレビュー依頼を外します（依頼が外れれば取得対象から消えます）。
