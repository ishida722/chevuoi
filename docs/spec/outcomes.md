# 終端状態

**すべての実行は、次のいずれかの終端状態で終わります。「なんとなく止まった」状態を作りません。**

| 終端状態 | 意味 | worktree |
|---|---|---|
| `done` | 経路を歩き切った。PR 作成済み | 削除 |
| `needs_human` | 仕様が曖昧 / レビュー未収束 / 承認待ち | **残す** |
| `failed_gate` | 決定的ゲートが上限回数落ちた | **残す** |
| `oscillation` | 同一 diff に戻った（収束しない） | **残す** |
| `failed_budget` | 壁時計 / 総試行数の予算超過 | **残す** |
| `abandoned` | チケットが消えた / 外部で変更された | 削除 |

## 判定の優先順位

**決定的ゲート → 予算 → 経路の終端** の順で判定します。LLM の自己申告（「完了しました」）は判定に一切使いません。

## needs_human のサブ分類

`needs_human` は理由で細分化します。打ち手が異なるため、区別が必要です。

| 理由 | 状況 |
|---|---|
| `ambiguous_ticket` | チケットが曖昧で、受け入れ基準を抽出できなかった |
| `review_unconverged` | レビューがラウンド上限までに収束しなかった |
| `unmapped_tag` | タグからプロジェクトを特定できなかった |
| `approval_required` | design 経路で人間の承認を待っている |
| `reviewer_abstained` | レビュアーが判断不能を申告した |
| `reroute_exhausted` | 経路変更が2回要求された |

## 終端状態が持つ情報

終端状態には、次の情報を添えます。

- 理由（サブ分類）
- PR の URL（`done` の場合）
- 未解決の所見の一覧
- 残した worktree のパス（残した場合。チケットのコメントにも記載し、人間へ伝える）

終端状態のチケットへの反映方法は {doc}`task-sources` を参照してください。
