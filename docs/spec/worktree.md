# 作業隔離（worktree）

実装を伴う経路では、git worktree で作業を隔離します。

## 仕様

- ブランチ名は `chevuoi/<source>-<external_id>` として、チケットの外部 ID から決定的に導出します
- worktree の作成は経路の先頭ノードで行い、必要とする経路（implement / trivial）だけが実行します
- 新規ブランチは、常にリモートの既定ブランチ（通常は `main`）の最新コミットから分岐させます。作成前にリモートへ問い合わせて既定ブランチを確定し、そのブランチを取得し直すため、本体側のチェックアウトが古くても別ブランチでも作業の起点は揃います
  - 既定ブランチ名はローカルの `origin/HEAD` からは引きません。`origin/HEAD` は既定ブランチの改名に追従せず、改名前のブランチから分岐し続けるためです
  - 取得は refspec を明示して行います。`--single-branch` クローンのように既定の refspec が既定ブランチを含まない場合でも取得できるようにするためです
  - 取得や既定ブランチの解決に失敗した場合は、古いベースで黙って作らずエラーにします。`origin` を持たないリポジトリだけは例外で、リポジトリの HEAD から分岐します
- 新規ブランチに upstream は設定しません。worktree 内でワークフローが素の `git push` / `git pull` を実行したときにベースブランチへ作用させないため、また共有の `.git/config` への書き込みを避けるためです（下記「並列実行」）
- 同名のローカルブランチが既にある場合は、そのブランチをそのまま使います（再実行で過去の成果を捨てないため）。この場合は分岐元を作り直さないので、最新の既定ブランチには追従しません
- 削除は終端状態に依存します（{doc}`outcomes` の表を参照）。失敗系の終端では人間の調査のために残します
- worktree を残した場合は、そのパスを終端状態に記録し、チケットのコメントにも記載します

## 後始末

`vuoi gc` コマンドで、終端済みかつ指定日数以上経過した worktree を削除します。このコマンドは最初のリリースから用意します。

## 並列実行

ラン間の並列実行時、worktree は別ディレクトリになるため衝突しません。

worktree の作成では共有のリポジトリに対して `git fetch` を実行しますが、更新する ref は既定ブランチの remote-tracking ref だけで、同時に走っても書き込む値は同じになるため衝突しません。一方、分岐元に remote-tracking ref を指定して upstream を設定すると、共有の `.git/config` の書き込みが並列作成で衝突します（`could not lock config file`）。upstream を設定しないのはこれを避けるためでもあります。
