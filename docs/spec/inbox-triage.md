# Inbox トリアージ

## 位置づけ

副次タスクの自動起票（{doc}`proposals`）を入れた結果、Inbox には似たカード・既に解決済みのカードが溜まります。Inbox トリアージは、**カード集合そのものを入力**として、重複を代表カードへ集約し、解決済みのカードを畳み、残りに読む順序の手がかり（ラベル）を付けるバッチ機能です。人間の判断を置き換えるのではなく、人間が読むべきカードの枚数を減らすことが目的です。

同じ「triage」でも、{doc}`triage` が扱う**経路の選択（ルーティング）**とは別物です。

| 呼称 | 対象 |
|---|---|
| ルーティング（{doc}`triage`） | 1 枚のカード → 適用するワークフロー |
| Inbox トリアージ（本章） | Inbox のカード集合 → 集約・畳み込み・ラベル |

## 非目標

- **カードを Ready へ昇格させません。** 自動起票カードの自動実行禁止（{doc}`overview`）を維持します。トリアージは読む枚数を減らすだけで、実行の可否には関与しません。
- **カードを削除しません。** アーカイブ（可逆）までとします。
- **人間が書いたカードを改変しません。** 人間起票カードは重複クラスタの代表にはなりますが、それ自身は畳みません。
- Inbox 以外のリスト（Ready / In Progress / In Review）のカードは対象外です。人間が動かした時点で管轄外とします。

## 実行単位

`vuoi triage` の 1 回の実行を 1 トリアージランとします。入力は Inbox のカード集合、出力はカードの状態変更と実行レポートです。

- プロジェクトには紐づきません。プロジェクトは各カードの属性（タイトル先頭タグ）として扱い、判定はプロジェクトごとにグループ化して行います。
- `vuoi run` の中では実行しません。並行して起票が走ると Inbox のスナップショットが揺れ、判定が実行順に依存するためです。別のタイマーで、頻度を落として回します。

## 対象カードの決定（決定的）

次をすべて満たすカードだけを判定対象とします。

| 条件 | 理由 |
|---|---|
| Inbox リストにある | 人間が動かしたカードは管轄外 |
| 本文に `vuoi:` フッターがある（自動起票） | 人間が書いたカードを畳まない |
| 作成から `settle_minutes`（既定 10 分）以上経過している | 実行中のランが今まさに起票したカードを触らない |
| 前回の判定時から内容が変わっている、または前回が予算超過だった | 変化のないカードを再判定しない（コスト） |
| 前回のランが計画だけを残して実行に至っていない（dry-run・適用失敗・途中クラッシュ） | 計画済みのカードから再開する |

Inbox の全カード（人間起票を含む）は、重複クラスタの**代表候補**としては読み込みます。

## 判定の 3 層

### 第 1 層 — 決定的な事前判定（LLM 不使用）

| 条件 | 判定 |
|---|---|
| 同一プロジェクト内に正規化タイトル完全一致のカードがある | `duplicate`（照会不要） |
| 本文が空、**かつ** 根拠（evidence）が 1 件もない | `needs_info` |
| フッターの `base` コミット以降、evidence の指すパスがベースで一度も変更されていない | `keep`（照会不要） |
| evidence の指すパスがベースに存在しない | 第 2 層（解決済みか要確認） |
| 類似度が閾値以上のペアがある | 第 2 層（同一かどうか要確認） |
| 上記以外 | `keep` |

evidence は起票時に任意なので、evidence を持たない自動起票カードは珍しくありません。`needs_info` の条件を「本文が空**または** evidence なし」にすると、そうしたカードが重複判定に到達せず、本機能の第一の目的が働かなくなります。条件は必ず「かつ」とします。

### 第 2 層 — LLM による判定（第 1 層で決まらなかったものだけ）

- 重複判定: 候補ペアを渡し、同一かどうかと確信度・理由だけを返させます。リポジトリは見せません。
- 解決済み判定: ベース参照のチェックアウトを作業ディレクトリにして、読み取り専用で確かめさせます。
- 1 ランの照会回数には上限（`max_judgments_per_run`）を置きます。予算は**重複判定を先に**使い、残りで解決済み判定を行います。重複の畳み込みのほうが枚数を減らす効果が大きく、解決済み判定は次のランへ持ち越しても損失がないためです。
- 重複の候補ペアには別の上限（`max_pairs_per_run`）を置きます。第 1 層で確定する完全一致のペアは照会しないので、この上限を消費しません。
- どちらの上限で溢れた分も、判定せずに `triage/review` ラベルだけを付け、台帳に「予算超過」として残して次のランで拾い直します。黙って捨てません。

### 第 3 層 — 棄権パス（必須）

確信度が high でない、出力が解析できない、実行に失敗した場合は、いずれも「人間が見る」判定とします。カードには何もせず、ラベルだけを付けます。必ずどれかを選ばされる判定器は必ず間違えるためです。

## 行動の決定表

先に一致した行を採ります。

| # | 条件 | 行動 | 外部作用 |
|---|---|---|---|
| 1 | 対象外カード | `skip` | なし |
| 2 | 重複が確定し、代表が自分でない | `merge` | 代表へ集約コメント → 自分にコメント → アーカイブ |
| 3 | 解決済みが確定し、決定的シグナルがある | `archive` | 理由コメント → アーカイブ |
| 4 | 情報不足 | `label` | `triage/needs-info` |
| 5 | 棄権 / 上限超過 | `label` | `triage/review` |
| 6 | それ以外 | `keep` | なし |

- 行 2・行 3 は、`--apply` を付けていなければラベル（`triage/duplicate` / `triage/stale`）の計画に降格し、dry-run では外部作用そのものを行いません。
- 行 4 を行 2・行 3 より下に置くのは意図的です。情報が薄いカードほど重複している見込みが高く、「本文が空だから人間に書き足させる」より「代表カードへ畳む」ほうが読む枚数が減ります。
- 行 6 は外部作用を持ちません。全カードに付くラベルは読む順序の手がかりにならないためです。

代表カードは決定的に選びます。人間起票カードがクラスタにあればそれを代表とし、無ければ最も古いカードを代表とします。

## 冪等性

- 台帳に計画を書く → 外部作用を実行する → 台帳に適用済みを書く、の順で行います。途中でクラッシュしても、次のランは計画済みのカードから再開します。
- アーカイブとラベル付けはもともと冪等です。コメントは冪等キー（`digest`）を持ち、同じ digest のコメントが既にあれば投稿しません。
- トリアージが残すコメントは 1 行目を `🤖 triage:` で始めます。これを外すと、カード処理側が人間の追加指示として読んでしまいます。
- 台帳を失っても真実源はタスクソース側の状態（アーカイブ済み・ラベル）であり、再判定のコストが増えるだけで結果は変わりません。

## 安全側の既定

- 既定は dry-run です。破壊的操作は `--apply` の明示を必要とします。
- 削除ではなくアーカイブ（可逆）だけを行い、必ず理由コメントを残します。
- 「解決済み」の根拠はベース参照だけとします。他のブランチや未マージの PR に修正があっても解決済みとは見なしません。判定が実行時点のブランチ状況に依存しないためです。
- 類似度の閾値には根拠がありません。dry-run で運用して較正してから `--apply` を使います。

## 設定

`[triage]` セクションは省略できます（すべて既定値で動きます）。

```toml
[triage]
enabled = true
model = "haiku"                 # 判定は分類なので軽量モデルで足りる
similarity = "trigram"          # 類似度の実装
similarity_threshold = 0.55     # dry-run 運用で較正する
max_pairs_per_run = 20          # LLM に照会する重複候補ペアの上限
max_judgments_per_run = 30      # 1 ランの LLM 呼び出し総数の上限
settle_minutes = 10             # これより新しいカードは触らない
apply = false                   # 既定は dry-run（CLI の --apply が上書きする）
ledger_path = "~/.local/state/vuoi/triage.json"

[projects.MIRAI]
path = "/home/ubuntu/projects/mirai"
base_ref = "origin/main"        # 省略時は origin/HEAD を解決する
```
